# 나만의 커뮤니티 기획서 - 보완점

원본 기획서(`나만의 커뮤니티 기획서.txt`)를 검토한 결과를 정리한 문서입니다.

## 1. 빠진 페이지 (가장 시급)

- **게시글 작성/수정 페이지가 없습니다.** 목록·상세 페이지만 있고 "글쓰기" 페이지가 기획서에 없습니다. 코드 리뷰 요청, 잡담 글 등 콘텐츠 유형별로 입력 폼이 달라질 수 있어서 별도 항목으로 반드시 넣어야 합니다.
- **알림 페이지/드롭다운**: 팔로우, 좋아요, 댓글, 대댓글이 있는데 정작 "누가 내 글에 좋아요를 눌렀는지"를 알려주는 알림 기능이 없습니다. 커뮤니티 재방문율에 큰 영향을 주는 기능이라 우선순위 있게 넣는 걸 추천합니다.
- **이용약관 / 개인정보처리방침 페이지**: 회원가입 시 이메일·전화번호 등 개인정보를 수집하므로 법적으로 필요합니다.
- **404 / 에러 페이지, 빈 상태(empty state) 화면**: 검색 결과 없음, 팔로우한 사람 없음, 게시글 없음 등의 케이스를 어떻게 보여줄지 고려가 안 되어 있습니다.

## 2. 핵심 기능인데 빠진 것 — 코드 하이라이팅

프론트엔드 코딩 커뮤니티인데 **코드 블록/문법 강조(syntax highlighting)** 언급이 전혀 없습니다. 이게 없으면 "코드 리뷰하기", "어려운 JS코드 풀기" 같은 핵심 기능 아이디어가 사실상 무의미해집니다. Markdown 에디터 + 코드 하이라이팅 라이브러리(예: Prism.js, highlight.js) 도입을 페이지별 특징 단계에서 구체화해야 합니다.

## 3. 카테고리/태그 체계 부재

"코드 리뷰", "JS 어려운 문제", "잡담"이 아이디어로만 나열되어 있고, 실제로 게시글을 어떻게 분류할지(카테고리 탭? 태그 검색?) 구조가 없습니다. 언어별 태그(JS, React, CSS 등)나 글 유형(질문/리뷰/잡담) 분류가 있어야 목록 페이지의 "인기 게시물/최신 게시물" 필터링도 의미가 생깁니다.

## 4. 회원가입 항목 재검토

- **전화번호가 정말 필요한가요?** 코딩 커뮤니티에 전화번호 수집은 개인정보 과다 수집 소지가 있고, 사용자 가입 장벽만 높입니다. 본인 인증이 목적이 아니라면 빼는 걸 권장합니다.
- **이메일 인증 절차**가 빠져 있습니다. 회원가입 후 이메일 인증 메일 발송 여부를 정해야 합니다.
- **비밀번호 찾기**가 로그인 페이지에 버튼만 있고, 실제 흐름(이메일 인증 → 재설정 링크 → 새 비밀번호)이 명시되어 있지 않습니다.
- 소셜 로그인(GitHub 로그인 등)을 고려할지도 정해두면 좋습니다. 개발자 커뮤니티 특성상 GitHub 로그인 수요가 큽니다.

## 5. 목록/검색 기능 구체화 필요

- **검색 버튼**만 있고 검색 범위(제목만? 본문 포함? 작성자? 태그?)가 정의되어 있지 않습니다.
- **페이지네이션 또는 무한스크롤** 방식 결정이 없습니다. 게시글이 많아지면 반드시 필요합니다.
- "인기 게시물"의 **정렬 기준**(좋아요 수? 댓글 수? 조회수? 기간별 가중치?)이 불명확합니다.

## 6. 신고/운영 관련 기능 부재

커뮤니티인 이상 어뷰징(스팸, 욕설, 도배)이 반드시 발생합니다. **신고 버튼**, **차단 기능**, 최소한의 **관리자 페이지**(신고 처리, 유저 제재) 없이는 운영이 어렵습니다. 개인 프로젝트라 당장 필요 없다면 "추후 확장" 항목으로라도 남겨두는 게 좋습니다.

## 7. 좋아요 로직 디테일

"좋아요 버튼"만 있고 중복 클릭 방지, 좋아요 취소, 로그인 안 한 유저의 좋아요 클릭 시 처리(로그인 페이지로 유도) 등 예외 상황이 정의되어 있지 않습니다.

## 8. 기술적/디자인 고려사항

- **기술 스택**이 기획서에 전혀 없습니다. 프론트엔드(React 등), 백엔드/DB(Supabase 연동 등), 배포 방식을 정리해두면 이후 설계가 훨씬 수월합니다.
- "어두운 프론트엔드 느낌"이라는 색상 테마가 추상적입니다. 컬러 팔레트 디자인 시스템처럼 실제 Primary/Background/Text hex 값을 미리 정의해두면 좋습니다.
- **반응형(모바일) 대응** 여부가 언급되지 않았습니다.

## 9. 우선순위(MVP) 구분 제안

현재 기획서는 모든 기능이 동일한 우선순위로 나열되어 있어, 실제 개발 시 범위가 커 보입니다. 예를 들어:

- **1차(MVP)**: 로그인/회원가입, 게시글 CRUD + 코드 하이라이팅, 목록/상세, 좋아요, 댓글
- **2차**: 팔로우, 알림, 대댓글, 태그 필터링
- **3차**: 신고/차단, 관리자 페이지, 소셜 로그인

이렇게 단계별로 나눠두면 실제 구현 순서를 잡을 때 헤매지 않을 수 있습니다.
