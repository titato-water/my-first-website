나만의 커뮤니티 기획서 — Devision

원본 기획서와 보완점 검토 결과를 반영해 확정한 최종 버전입니다.

1. 프로젝트 개요

  • 사이트 이름: Devision
  • 커뮤니티 주제: 프론트엔드 코딩 커뮤니티
  • 색상 테마: 다크 테마 (어두운 프론트엔드 느낌)
  • 분위기: 차분한
  • 참고 사이트: velog.io

2. 개발 우선순위 (MVP 단계 구분)

단계포함 기능
1차 (MVP)로그인/회원가입, 게시글 작성·수정·목록·상세, 코드 하이라이팅, 좋아요, 댓글
2차팔로우, 알림, 대댓글, 카테고리/태그 필터링, 검색
3차 (확장)신고/차단, 관리자 페이지, 소셜 로그인(GitHub)

3. 페이지별 상세 기획

3-1. 로그인 페이지

  • 이메일(계정) 입력
  • 비밀번호 입력
  • 로그인 버튼
  • 회원가입 버튼
  • 비밀번호 찾기 버튼 — 등록된 이메일 입력 → 재설정 링크 발송 → 새 비밀번호 설정

3-2. 회원가입 페이지

  • 이메일(계정)
  • 비밀번호
  • 비밀번호 확인
  • 닉네임(이름)
  • 전화번호 (삭제 — 개인정보 과다 수집 방지)
  • 회원가입 버튼
확정: 별도 인증 메일 발송 없이, 이메일 중복 여부만 검사하여 가입을 처리합니다.

3-3. 마이페이지

  • 프로필 카드
  • 작성한 게시글 / 작성한 댓글
  • 좋아요 누른 게시글 / 좋아요 누른 댓글
  • 팔로우 / 팔로워 목록

게시글 작성/수정 페이지 NEW

  • 제목
  • 카테고리/태그 선택 (코드 리뷰, JS 문제풀이, 잡담 등)
  • 본문: Markdown 에디터 + 코드 블록 문법 강조 (Prism.js / highlight.js)
  • 등록 / 수정 버튼

3-5. 게시물 목록

  • 검색: 제목 + 본문 + 작성자 + 태그 범위
  • 카테고리/태그 필터 탭
  • 팔로우한 사람의 최신 글 / 인기 글
  • 인기 게시물 (좋아요 수 + 댓글 수 가중치, 최근 기간 우선)
  • 최신 게시물
  • 목록 탐색 방식: 무한 스크롤
  • 게시글 카드: 제목, 작성자, 작성일, 태그, 댓글 수, 인기 댓글 3개

3-6. 게시물 상세

  • 제목 / 태그 / 작성자 / 작성일
  • 본문 (코드 하이라이팅 적용)
  • 좋아요 수 + 좋아요 버튼 — 중복 클릭 방지, 취소 가능, 비로그인 시 로그인 유도
  • 댓글 영역

3-7. 댓글 기능

  • 댓글 작성
  • 댓글 좋아요
  • 대댓글

알림 NEW

  • 알림 대상: 좋아요, 댓글, 대댓글, 팔로우
  • 헤더 알림 아이콘 + 알림 드롭다운/알림 페이지

기타 페이지 NEW

  • 이용약관 / 개인정보처리방침 페이지
  • 404 페이지
  • 빈 상태(empty state) 화면: 검색 결과 없음, 팔로워 없음, 게시글 없음 등

4. 향후 확장 기능 (3차)

  • 게시글/댓글 신고 버튼
  • 유저 차단 기능
  • 관리자 페이지 (신고 처리, 유저 제재)
  • 소셜 로그인 (GitHub 등)

5. 디자인 가이드

  • 다크 테마 기반, 별도 컬러 팔레트 문서로 Primary/Background/Text 색상 정의 예정
  • 반응형(모바일) 대응 고려

7. DB 구조 설계

모든 테이블명은 서비스명(Devision)에 맞춰 DV_ 접두사를 사용합니다.

테이블 목록 개요

테이블명설명
DV_USERS사용자 정보
DV_POSTS게시물 정보
DV_TAGS태그 마스터
DV_POST_TAGS게시물-태그 매핑 (N:M)
DV_COMMENTS댓글 / 대댓글
DV_POST_LIKES게시물 좋아요 (N:M)
DV_COMMENT_LIKES댓글 좋아요 (N:M)
DV_FOLLOWS팔로우 관계 (N:M, self)
DV_NOTIFICATIONS알림

DV_USERS — 사용자

전화번호 컬럼은 제외했으며, 이메일은 가입 시 중복 검사만 수행합니다(별도 인증 컬럼 없음).

컬럼명타입제약조건설명
user_idBIGSERIALPK, AUTO INCREMENT사용자 번호
emailVARCHAR(255)UNIQUE, NOT NULL로그인 계정 (중복검사 대상)
passwordVARCHAR(255)NOT NULL비밀번호 (해시 저장)
nicknameVARCHAR(50)UNIQUE, NOT NULL닉네임(이름)
created_atTIMESTAMPNOT NULL, DEFAULT now()가입일

DV_POSTS — 게시물

인기순 정렬에 쓰이는 카운트 컬럼은 조회 성능을 위해 비정규화하여 보관합니다.

컬럼명타입제약조건설명
post_idBIGSERIALPK, AUTO INCREMENT게시물 번호
user_idBIGINTFK → DV_USERS.user_id, NOT NULL작성자
titleVARCHAR(200)NOT NULL제목
contentTEXTNOT NULL본문 (마크다운 + 코드블록 원문 저장)
categoryVARCHAR(30)NOT NULL대분류 (코드리뷰 / 문제풀이 / 잡담)
like_countINTNOT NULL, DEFAULT 0좋아요 수 (캐시)
comment_countINTNOT NULL, DEFAULT 0댓글 수 (캐시)
created_atTIMESTAMPNOT NULL, DEFAULT now()작성일
updated_atTIMESTAMPNULL 허용수정일

DV_TAGS — 태그 마스터

컬럼명타입제약조건설명
tag_idBIGSERIALPK, AUTO INCREMENT태그 번호
nameVARCHAR(30)UNIQUE, NOT NULL태그명

DV_POST_TAGS — 게시물-태그 매핑

컬럼명타입제약조건설명
post_idBIGINTPK(복합), FK → DV_POSTS.post_id게시물 번호
tag_idBIGINTPK(복합), FK → DV_TAGS.tag_id태그 번호

DV_COMMENTS — 댓글 / 대댓글

parent_comment_id로 자기 자신을 참조해 대댓글을 표현합니다 (NULL이면 최상위 댓글).

컬럼명타입제약조건설명
comment_idBIGSERIALPK, AUTO INCREMENT댓글 번호
post_idBIGINTFK → DV_POSTS.post_id, NOT NULL어떤 게시물의 댓글인지
user_idBIGINTFK → DV_USERS.user_id, NOT NULL작성자
parent_comment_idBIGINTFK → DV_COMMENTS.comment_id, NULL 허용대댓글인 경우 부모 댓글
contentTEXTNOT NULL댓글 내용
created_atTIMESTAMPNOT NULL, DEFAULT now()작성일

DV_POST_LIKES — 게시물 좋아요

복합 PK로 같은 사용자의 중복 좋아요를 막습니다.

컬럼명타입제약조건설명
user_idBIGINTPK(복합), FK → DV_USERS.user_id좋아요 누른 사용자
post_idBIGINTPK(복합), FK → DV_POSTS.post_id좋아요 대상 게시물
created_atTIMESTAMPNOT NULL, DEFAULT now()좋아요 누른 시각

DV_COMMENT_LIKES — 댓글 좋아요

컬럼명타입제약조건설명
user_idBIGINTPK(복합), FK → DV_USERS.user_id좋아요 누른 사용자
comment_idBIGINTPK(복합), FK → DV_COMMENTS.comment_id좋아요 대상 댓글
created_atTIMESTAMPNOT NULL, DEFAULT now()좋아요 누른 시각

DV_FOLLOWS — 팔로우 관계

DV_USERS를 자기 자신과 N:M으로 연결합니다.

컬럼명타입제약조건설명
follower_idBIGINTPK(복합), FK → DV_USERS.user_id팔로우 하는 사람
following_idBIGINTPK(복합), FK → DV_USERS.user_id팔로우 받는 사람
created_atTIMESTAMPNOT NULL, DEFAULT now()팔로우 시작 시각

DV_NOTIFICATIONS — 알림

target_id가 가리키는 대상은 type에 따라 게시물 또는 댓글로 달라집니다.

컬럼명타입제약조건설명
notification_idBIGSERIALPK, AUTO INCREMENT알림 번호
receiver_idBIGINTFK → DV_USERS.user_id, NOT NULL알림 받는 사용자
sender_idBIGINTFK → DV_USERS.user_id, NOT NULL알림을 발생시킨 사용자
typeVARCHAR(20)NOT NULLLIKE_POST / LIKE_COMMENT / COMMENT / REPLY / FOLLOW
target_idBIGINTNOT NULL대상 게시물/댓글 번호
is_readBOOLEANNOT NULL, DEFAULT false읽음 여부
created_atTIMESTAMPNOT NULL, DEFAULT now()알림 발생 시각

테이블 연결 관계 (ERD 요약)

  • DV_USERS 1 : N DV_POSTS — 한 사용자가 여러 게시물 작성
  • DV_USERS 1 : N DV_COMMENTS — 한 사용자가 여러 댓글 작성
  • DV_POSTS 1 : N DV_COMMENTS — 한 게시물에 여러 댓글
  • DV_COMMENTS 1 : N DV_COMMENTS (self) — 댓글 하나에 여러 대댓글
  • DV_POSTS N : M DV_TAGS (DV_POST_TAGS 경유) — 게시물 ↔ 태그 다대다
  • DV_USERS N : M DV_POSTS (DV_POST_LIKES 경유) — 좋아요
  • DV_USERS N : M DV_COMMENTS (DV_COMMENT_LIKES 경유) — 댓글 좋아요
  • DV_USERS N : M DV_USERS (DV_FOLLOWS 경유, self) — 팔로우/팔로워
  • DV_USERS → DV_NOTIFICATIONS — 한 사용자가 여러 알림을 받음 (receiver_id, sender_id 모두 DV_USERS 참조)

향후 확장 예정 테이블 (3차 기능)

신고/차단, 관리자 기능을 위한 DV_REPORTS(게시물/댓글 신고 내역), DV_BLOCKS(사용자 간 차단 관계)는 이름만 예정해두고 상세 설계는 보류합니다.
확정 사항: 회원가입 시 이메일은 중복확인만으로 가입 처리하며, 별도의 가입 확인 메일 절차는 두지 않는다. 그 외 항목은 기획서_보완점.md에서 제안한 권장 방향을 따른다.
